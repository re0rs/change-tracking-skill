## 变更概要

优化 change-tracking skill 的 Hook 触发机制，解决每次用户输入或文件修改都触发检查的问题，显著减少对工作流的干扰。

## 问题背景

原有设计存在以下效率问题：
1. `UserPromptSubmit` Hook 每次用户输入都触发关键词检测
2. `PostToolUse` 文件修改 Hook 每次文件操作都询问是否生成记录
3. `PostToolUse` 终端命令 Hook 每次执行命令都检查是否是 git push

## 具体改动

### 1. 删除 user-confirmation hook

**原因**：每次用户输入（包括简单的"好的"、"可以"等）都会触发关键词检测，即使会话中没有任何代码修改。

### 2. 修改 code-modification hook

**改动前**：
```json
{
  "trigger": "PostToolUse",
  "matcher": "fs_write|str_replace|fs_append",
  "action": { "type": "agent", "prompt": "..." }
}
```

**改动后**：
```json
{
  "trigger": "Stop",
  "action": { "type": "agent", "prompt": "..." }
}
```

**原因**：每次文件修改都询问太频繁，改为会话结束时统一询问一次。

### 3. 修改 git-push hook

**改动前**：
```json
{
  "action": { "type": "agent", "prompt": "检查命令是否包含 git push..." }
}
```

**改动后**：
```json
{
  "action": { "type": "command", "command": "node scripts/check-git-push.js" }
}
```

**原因**：使用轻量级脚本做前置判断，不匹配则静默通过，避免每次终端命令都注入 agent prompt。

### 4. 新增 check-git-push.js 脚本

脚本逻辑：
- 检查命令是否匹配 `git push` 模式
- 检查命令是否执行成功（Exit Code: 0）
- 只有两者都满足才输出 agent prompt，否则静默退出

## 影响分析

### 优化效果

| 场景 | 优化前 | 优化后 |
|------|--------|--------|
| 用户输入 | 每次触发关键词检测 | 不触发 |
| 文件修改 | 每次询问 | 会话结束时询问一次 |
| 终端命令 | 每次注入 prompt 检查 | 脚本静默判断，不匹配则跳过 |

### 兼容性
