# PersistenceService - 持久化服务

## 职责

负责将生成的变更记录文档保存到文件系统。

## 存储位置

**目录**：项目根目录下的 `docs/change-logs/`

**文件名格式**：`YYYY-MM-DD_HHmmss_简短描述.md`

## 持久化流程

### 1. 确保目录存在

首先检查并创建存储目录：

```bash
# 检查目录是否存在
Test-Path "docs/change-logs"

# 如果不存在，创建目录
New-Item -ItemType Directory -Path "docs/change-logs" -Force
```

或使用 fs_write 工具时，Kiro 会自动创建父目录。

### 2. 生成文件路径

```
{project_root}/docs/change-logs/{YYYY-MM-DD_HHmmss_简短描述}.md
```

示例：
```
d:\my-project\docs\change-logs\2024-03-15_143022_修复登录验证.md
```

### 3. 写入文件

使用 `fs_write` 工具将文档内容写入文件：

```
fs_write({
  path: "{full_path}",
  content: "{markdown_content}"
})
```

### 4. 验证写入结果

确认文件已成功创建，并向用户报告保存位置。

## 错误处理

### 目录创建失败

**可能原因：**
- 权限不足
- 磁盘空间不足
- 路径过长

**处理方式：**
1. 尝试一次重试
2. 失败后向用户显示错误信息
3. 建议解决方案（如检查权限、清理磁盘空间）

### 文件写入失败

**可能原因：**
- 权限不足
- 磁盘已满
- 文件被占用

**处理方式：**
1. 向用户显示错误信息
2. 将文档内容输出到聊天窗口，方便用户手动保存
3. 提供重试选项

### 文件名冲突

如果同一秒内生成多个文档（极少见），文件名可能冲突。

**处理方式：**
- 在文件名末尾添加序号：`YYYY-MM-DD_HHmmss_描述_1.md`

## 用户交互

### 成功时

```
✅ 变更记录已保存到：docs/change-logs/2024-03-15_143022_修复登录验证.md
```

### 失败时

```
❌ 保存变更记录失败：{错误信息}

文档内容已生成，你可以手动保存以下内容：

---
{文档内容}
---

建议操作：
1. 检查 docs/change-logs 目录是否有写入权限
2. 确认磁盘空间充足
3. 或手动创建文件并粘贴上述内容
```

## 最佳实践

1. **及时保存**：生成文档后立即持久化，避免内容丢失

2. **版本控制**：建议将 `docs/change-logs/` 目录纳入 Git 管理

3. **定期清理**：历史记录过多时，可考虑归档旧文档

4. **备份重要记录**：关键变更记录建议额外备份
