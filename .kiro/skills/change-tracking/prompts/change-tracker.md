# ChangeTracker - 变更追踪控制器

## 职责

作为变更追踪系统的核心控制器，协调 GitCollector、DocumentGenerator、PersistenceService 完成完整的变更记录生成流程。

## 触发条件判断

### shouldTrack() - 判断是否应触发变更追踪

根据触发上下文判断是否应该启动变更追踪：

**代码修改触发 (PostToolUse + fs_write/str_replace/fs_append)**
- ✅ 触发：有实际的代码文件被修改
- ❌ 不触发：修改的是变更记录文件本身（docs/change-logs/）

**用户确认触发 (UserPromptSubmit)**
- ✅ 触发：用户消息包含确认关键词（好的、完成、成功、OK 等）
- ✅ 触发：用户消息包含修复成功关键词（修好了、解决了、正常了等）
- ❌ 不触发：用户在询问问题或提出新需求

**Git Push 触发 (PostToolUse + execute_pwsh/execute_bash)**
- ✅ 触发：命令包含 `git push` 且执行成功
- ❌ 不触发：命令不包含 `git push`
- ❌ 不触发：push 失败

## 主控制流程

### track() - 执行完整的变更追踪流程

```
1. 判断触发条件
       ↓
2. 询问用户确认（如需要）
       ↓ (用户确认)
3. 收集 Git 信息 (GitCollector)
       ↓
4. 收集变更内容
       ↓
5. 收集分析内容（根因、踩坑、影响）
       ↓
6. 生成文档 (DocumentGenerator)
       ↓
7. 持久化保存 (PersistenceService)
       ↓
8. 向用户报告结果
```

### 用户确认流程

**询问方式：**

```
代码修改已完成。是否需要生成变更记录（留痕文档）？

- 生成：我将收集本次修改的信息并生成详细的变更记录
- 跳过：本次不生成变更记录
```

**用户响应处理：**
- 确认生成：继续执行后续步骤
- 跳过/拒绝：终止流程，不再重复询问
- 未明确回应：不执行任何操作，等待用户明确指示

## 信息收集

### 变更内容收集

从当前会话上下文中收集：

1. **修改的文件列表**
   - 从 Agent 的工具调用历史中提取
   - 记录 fs_write、str_replace、fs_append 操作的文件

2. **具体改动点**
   - 每个文件的修改位置（函数名或行号）
   - 修改的具体内容
   - 修改的原因

3. **变更类型识别**
   - 根据用户描述和代码内容判断
   - Bug修复、新功能、重构、性能优化等

### 根因分析收集（仅 Bug 修复）

当变更类型为"Bug修复"时，需要收集：

1. **问题症状**
   - 用户最初描述的问题现象
   - 错误信息或异常行为

2. **根本原因**
   - 问题产生的代码层面原因
   - 为什么会出现这个问题

### 踩坑记录收集

回顾整个开发过程，收集：

1. **阻塞问题**
   - 开发过程中遇到的阻塞性问题
   - 如何解决的

2. **误判记录**
   - 是否有错误的问题定位或判断
   - 为什么会误判

3. **误改记录**
   - 是否有错误的修改尝试
   - 为什么会误改
   - 后来如何发现并纠正

**收集方式：**
- 回顾会话历史中的调试过程
- 识别走过的弯路
- 记录每一次方向调整的原因

### 影响分析收集

分析本次变更的影响范围：

1. **接口变更**
   - 是否修改了函数签名
   - 是否修改了 API 接口
   - 是否修改了类的公共方法

2. **数据结构变更**
   - 是否修改了数据模型
   - 是否修改了数据库 schema
   - 是否修改了配置结构

3. **受影响模块**
   - 哪些模块依赖被修改的代码
   - 是否需要同步修改其他地方

**严格检查后**，如果确认无外部影响，标记为"无外部影响"。

### 代码差异收集

遵循精简原则：

1. **关键代码变更**
   - 只收集核心逻辑修改
   - 只收集接口变更
   - 只收集关键算法调整

2. **批量变更摘要**
   - 大量重命名：统计数量
   - 批量格式化：统计数量
   - 重复性修改：合并描述

3. **commit 链接**
   - 提供 Git commit hash
   - 方便读者查看完整 diff

## 错误处理

### Git 信息收集失败

- 不中断流程
- 在文档中标注"信息不可用"
- 继续收集其他信息

### 文档生成失败

- 向用户报告错误
- 输出已收集的信息
- 建议手动记录

### 持久化失败

- 向用户报告错误
- 将文档内容输出到聊天窗口
- 建议手动保存

## 完成报告

流程完成后，向用户报告：

**成功时：**
```
✅ 变更记录已生成并保存

📄 文件：docs/change-logs/2024-03-15_143022_修复登录验证.md
📝 类型：Bug修复
🏷️ 标签：安全, 用户认证
📂 修改文件：3 个
```

**部分成功时：**
```
⚠️ 变更记录已生成，但部分信息不可用

📄 文件：docs/change-logs/2024-03-15_143022_修复登录验证.md
⚠️ 注意：Git 分支信息不可用

建议在 Git 仓库中使用此功能以获取完整信息。
```

**用户跳过时：**
```
已跳过变更记录生成。如需后续生成，可以说"请生成变更记录"。
```
