# Change Tracking Skill

变更追踪技能 - 自动生成代码变更记录文档

## 元信息

- **名称**: change-tracking
- **版本**: 1.0.0
- **描述**: 在代码修改或 Bug 修复完成后，自动生成结构化的变更记录文档，便于追溯和交接

## 激活条件

当以下情况发生时，此 Skill 会被激活：

1. **代码修改完成后**：Agent 完成文件编辑操作（fs_write、str_replace、fs_append）
2. **用户确认修改成功**：用户在对话中表示修改完成或确认成功
3. **Git Push 操作**：检测到用户通过 Agent 执行 git push 命令

## 使用说明

### 自动触发

Skill 会通过 Hook 机制自动触发，无需手动调用：

- 代码修改完成后会询问是否生成变更记录
- 用户确认修改成功时自动生成
- 检测到 git push 后自动生成

### 手动触发

你也可以手动要求生成变更记录：

```
请为刚才的修改生成变更记录
```

或

```
生成留痕文档
```

## 变更记录内容

生成的变更记录包含以下信息：

### 元信息
- 唯一标识符 (UUID)
- 创建时间和完成时间
- Git 分支名称
- Commit Hash 或 Commit 范围
- 变更类型（Bug修复、新功能、重构等）
- 严重程度（仅 Bug 修复）
- 标签

### 变更内容
- 变更概要
- 详细描述
- 修改文件列表
- 具体改动（位置、改动内容、修改原因）

### 分析内容
- 根因分析（仅 Bug 修复）
- 踩坑记录（误判、误改及原因分析）
- 影响分析（接口变更、数据结构变更、受影响模块）
- 关键代码差异

## 存储位置

变更记录保存在：`docs/change-logs/YYYY-MM-DD_HHmmss_简短描述.md`

## 工作流程

```
1. 触发条件满足
       ↓
2. 询问用户是否生成（或自动触发）
       ↓
3. 收集 Git 信息（分支、commit、diff）
       ↓
4. 收集变更信息（文件、改动、原因）
       ↓
5. 分析影响和踩坑记录
       ↓
6. 生成 Markdown 文档
       ↓
7. 持久化到 docs/change-logs/
```

## 示例场景

### Bug 修复场景

修复了一个空指针异常后，变更记录会包含：
- 问题症状：用户点击按钮时页面崩溃
- 根本原因：未检查 user 对象是否为 null
- 踩坑记录：最初误判为前端问题，实际是后端接口返回了 null
- 影响分析：无外部影响

### 新功能场景

添加了用户登录功能后，变更记录会包含：
- 变更概要：实现用户登录功能
- 修改文件：auth.ts, login.vue, api.ts
- 影响分析：新增 /api/login 接口，需要前端配合

## 注意事项

1. Git 信息不可用时会优雅降级，标注"信息不可用"继续生成
2. 用户可以选择跳过生成，系统不会重复询问
3. 持久化失败时会显示错误并保留文档内容
